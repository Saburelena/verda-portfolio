# GIT COMMANDS (Personal Reference)

Основные команды Git, которые я использую ежедневно.  
Актуально для работы с локальным репозиторием и удалённым (GitLab / GitHub).

## Основные операции

| Команда                                      | Назначение                                                                   |
|----------------------------------------------|------------------------------------------------------------------------------|
| `git status`                                 | Показать текущее состояние: какие файлы изменены, добавлены, неотслеживаемые |
| `git add <file>`                             | Добавить файл в индекс (стейджинг)                                           |
| `git add .`                                  | Добавить все изменения в текущей папке в индекс                              |
| `git commit -m "сообщение"`                  | Зафиксировать изменения из индекса с описанием                               |
| `git log --oneline`                          | Посмотреть историю коммитов в кратком виде                                   |
| `git push`                                   | Отправить локальные коммиты в удалённый репозиторий                          |
| `git pull`                                   | Получить изменения из удалённого репозитория и слить с локальной веткой      |

## Навигация и ветвление

| Команда                                      | Назначение                                                                 |
|----------------------------------------------|----------------------------------------------------------------------------|
| `git checkout <branch>`                      | Переключиться на другую ветку                                              |
| `git checkout -b <new-branch>`               | Создать новую ветку и сразу переключиться на неё                           |
| `git branch`                                 | Показать список всех локальных веток                                       |
| `git branch -d <branch>`                     | Удалить локальную ветку (только если она уже влитa)                        |
| `git remote -v`                              | Показать привязанные удалённые репозитории                                 |
| `git remote add <name> <url>`                | Добавить новый удалённый репозиторий (например, зеркало на GitHub)         |

## Отмена и возврат

| Команда                                      | Назначение                                                                    |
|----------------------------------------------|-------------------------------------------------------------------------------|
| `git restore <file>`                         | Отменить **локальные изменения** в файле (вернуть как в последнем коммите)    |
| `git restore --staged <file>`                | Убрать файл из индекса (отменить `git add`)                                   |
| `git commit --amend`                         | **Изменить последний коммит**: обновить сообщение или добавить забытый файл   |
| `git reset --soft HEAD~1`                    | Отменить **последний коммит**, но **оставить изменения в индексе**            |
| `git reset --hard HEAD~1`                    | **Полностью удалить последний коммит и все его изменения** (осторожно!)       |
| `git revert <commit-hash>`                   | Создать **новый коммит**, который отменяет указанный (без перезаписи истории) |

## Работа с конфликтами

| Ситуация                                     | Что делать                                                                                                                                                           |
|----------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| При `git pull` возник конфликт               | 1. WebStorm автоматически откроет **Merge Conflicts**<br>2. Выбери: «Accept Yours», «Accept Theirs» или смешай вручную<br>3. Сохрани файл → `git add` → `git commit` |
| Нужно сравнить версии файла                  | В WebStorm: правой кнопкой → **Git → Compare with Branch**                                                                                                           |
| Хочу увидеть, кто и когда менял строку       | В WebStorm: правой кнопкой → **Git → Annotate **(Blame)                                                                                                              |

## Продвинутые сценарии

| Команда                                      | Назначение                                                                         |
|----------------------------------------------|------------------------------------------------------------------------------------|
| `git stash`                                  | Временно спрятать незакоммиченные изменения (чтобы переключиться на другую задачу) |
| `git stash pop`                              | Вернуть последние спрятанные изменения                                             |
| `git diff`                                   | Показать незаиндексированные изменения                                             |
| `git diff --staged`                          | Показать заиндексированные (готовые к коммиту) изменения                           |
| `git log --graph --all --oneline`            | Красивая визуализация истории всех веток                                           |

## Полезные советы

- **`--amend` безопасен**, пока ты **не пушил** коммит. После пуша — лучше использовать `revert`.
- **`reset --hard` — опасная команда**. Используй только если уверена, что не нужно сохранять изменения.
- **`revert` — лучший способ отмены в общих ветках** (main, develop), потому что не переписывает историю.
- **Коммиты пиши на английском** — даже в личном проекте. Это хорошая практика.
- **Один коммит = одна логическая задача** (например, «add text-wrap balance»).
- Перед `git push` — всегда делай `git pull`, чтобы избежать конфликтов.
- Если работаешь с **двумя репозиториями** (GitLab + GitHub):
  ```bash
  git remote add gitlab https://gitlab.com/...
  git remote add github https://github.com/...
  git push gitlab main
  git push github main

Общепринятая практика — Conventional Commits.
Она помогает автоматизировать changelog, релизы и просто делает историю понятной.

### Основные типы (используй на английском):

| Тип        | Когда использовать                                                      | Пример                                      |
|------------|-------------------------------------------------------------------------|---------------------------------------------|
| `feat`     | Добавление новой функциональности                                       | `feat: add dark mode support`               |
| `fix`      | Исправление бага                                                        | `fix: correct header alignment on mobile`   |
| `docs`     | Изменения в документации                                                | `docs: update CSS_PROPERTIES_DICTIONARY.md` |
| `style`    | Правки, не влияющие на логику: форматирование, пробелы, точки с запятой | `style: format globals.scss`                |
| `refactor` | Рефакторинг кода без изменения поведения                                | `refactor: extract header mixins`           |
| `perf`     | Улучшение производительности                                            | `perf: optimize image loading`              |
| `test`     | Добавление или правка тестов                                            | `test: add HTML validation for header`      |
| `chore`    | Рутинные задачи: обновление зависимостей, настройка сборки              | `chore: update husky config`                |
